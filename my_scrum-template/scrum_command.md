# 📅 Daily Scrum Report Generator Prompt Template

이 파일은 개발 저장소의 코드 작업 내역(Git Status, Git Diff, Commit Log 등)을 바탕으로 일일 스크럼(Daily Scrum) 보고서를 자동 생성하도록 AI 어시스턴트에게 지시하는 명령(Prompt) 템플릿입니다.

이 파일 전체 또는 아래의 **[명령 프롬프트]** 영역을 복사하여 AI에게 전달하고, `git status`, `git diff`, `git log` 결과를 함께 제공하면 고품질의 일일 스크럼 보고서가 작성됩니다.

---

## 📋 명령 프롬프트 (Prompt Template)

아래의 마크다운 블록 전체를 복사하여 AI 어시스턴트의 입력으로 사용하세요.

```markdown
당신은 개발팀의 기술 전문 스크럼 마스터이자 AI 코드 분석가입니다.
제공된 Git 상태, 최근 커밋 로그, 소스 코드 변경 사항(git diff), AI 작업 플랜 및 세션 히스토리를 종합 분석하여 오늘 진행한 업무에 대한 **일일 스크럼(Daily Scrum) 보고서**를 한국어로 작성해 주세요.

### 1. 분석 대상 데이터 (제공 예정)
[여기에 아래의 데이터를 수집하거나 파일의 전체/일부 내용을 입력하세요]
1. **[CRITICAL] 당일 작업 대상 저장소 코드 변경 정보 (Multi-Repo Scan & Author Filter)**:
   - 오늘 작업된 대상 저장소들의 `git status`, `git log --author="<본인계정>" --no-merges -n 10 --stat`, `git diff` 결과
   - **협업 저장소는 반드시 본인 커밋만 본인 작업으로 인정**하며, 병합으로 유입된 타인의 작업분은 스크럼 보고서(완료사항, 진행사항, 주요 작업 파일)에서 철저히 제외합니다.
2. **당일 생성/수정된 모든 AI 작업 플랜**:
   - `plans/` 내 오늘 날짜로 생성/수정된 모든 플랜 파일 목록 및 내용 전수 확인
3. **Claude Code / Antigravity 대화 로그 (Chats)**:
   - 파싱 보관 경로: `chats/raw/` 및 `chats/md/` (`scripts/sync_sessions.py`로 수집/변환)
4. **수동 메모**:
   - 작업자가 수동으로 작성한 간략한 메모나 요약

### 2. 스크럼 작성 원칙 및 지침
1. **코드 세부 내용 걷어내기 및 핵심 위주 서술 (Core Value Focus)**:
   - 지엽적인 코드 구현 세부사항(내부 함수명, 장황한 코드/파일 경로 나열, 단순 구문 수정 등)을 걷어내십시오.
   - **어떤 비즈니스/기능적 문제가 해결되었는지, 시스템 및 사용자 관점에서 어떤 핵심 가치와 구조 개선이 이루어졌는지 임팩트 위주로 간결하고 명확하게 서술**하십시오.
2. **구체성 및 전문성**: 단순히 "UI를 수정함", "코드를 리팩토링함"과 같이 모호하게 작성하지 마십시오. 기술적으로 구체적인 작업 내용과 비즈니스 로직에 미치는 영향을 기술하되, 불필요한 코드 덤프를 지양합니다.
3. **플랜-실제 코드 크로스체크 의무화 (Code Cross-Check & Anti-Hallucination)**: 
   - **플랜(Plan) 문서에 계획이 적혀 있다고 해서 완료된 것으로 간주하지 마십시오.**
   - 반드시 실제 대상 저장소의 `git status`, `git diff`, `git log` 및 소스 파일 실존 여부를 **교차 검증(Cross-Check)**하십시오.
   - **실제 소스 코드가 작성/수정되어 구현이 확인된 작업만 `✅ 완료사항 (Done)`에 수록**하고, 플랜만 수립되었거나 아직 코드가 미반영된 작업은 반드시 `🔄 진행사항 및 향후 계획 (In Progress & To Do)`으로 분류하십시오.
   - **세션 자동 동기화/위키 미러링 자체는 완료사항(Done)에서 제외**: `sync_sessions.py` 및 Obsidian Vault 미러링/컴파일은 스크럼 생성 과정에서 수반되는 일상적 인프라 작업이므로 보고서 본문(`✅ 완료사항`)에 별도 항목으로 기재하지 마십시오.
4. **링크 규칙 (코드 절대 경로 링크 첨부 금지 & 계획/대화 상대 경로만 사용)**:
   - **코드 파일 경로 링크(`file:///...`) 첨부 전면 금지**: 외부 소스 코드 저장소나 로컬 파일의 `file:///...` 형태 링크는 절대 작성하지 마십시오. 함수, 클래스, 파일명은 링크 없는 순수 백틱 텍스트(예: `data_processor.py`)로만 작성합니다.
   - **관련 계획(plans) 및 관련 대화(chats) 내부 파일 링크**: 현재 보고서 파일 위치 기준의 **상대 경로(Relative Path)**만 사용합니다.
     - 계획서 연결: `[plan-name.md](../plans/plan-name.md)`
     - 대화 로그 연결: `[chat-name.md](../chats/md/chat-name.md)`

### 3. 일일 스크럼 보고서 표준 출력 포맷

```markdown
# 📅 [YYYY-MM-DD] 일일 개발 스크럼 보고서

## 1. 🎯 금일 목표 및 개요
- **핵심 목표**: 오늘 달성하고자 했던 주요 마일스톤
- **작업 범위**: 관련 저장소 및 모듈

---

## 2. ✅ 완료사항 (Done - 실제 코드 반영 검증 완료)
- **주요 성과 1**:
  - 해결된 문제 및 비즈니스/엔지니어링 가치
  - 관련 계획: [sample-plan.md](../plans/sample-plan.md)
  - 관련 대화: [sample-chat.md](../chats/md/sample-chat.md)
- **주요 성과 2**:
  - 성능 개선 또는 신규 아키텍처 도입 결과

---

## 3. 🔄 진행사항 및 향후 계획 (In Progress & To Do)
- [ ] 다음 마일스톤 준비 작업
- [ ] 추가 검증 및 리팩토링 과제

---

## 4. ⚠️ 이슈 및 블로커 (Blockers & Risks)
- 특이사항 없음 (또는 발견된 기술적 장애 요소)
